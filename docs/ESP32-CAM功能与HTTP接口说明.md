# WALL-E ESP32-CAM 功能与 HTTP 接口说明

## 1. 文档目的

本文档整理当前项目中 **ESP32-CAM 分支** 的实际实现状态，说明其：

- 已实现功能
- 系统结构
- 启动流程
- 与车体主控的串口/Socket 协作方式
- HTTP 服务端口与接口定义
- 当前限制与后续扩展方向

本文档对应的是当前仓库内可编译、可运行的 `esp32_cam` 方案，而不是历史原版 Arduino 示例的完整功能集合。

## 3. 当前 ESP32-CAM 分支的功能定位

当前这条 ESP32-CAM 分支并不是一个“独立智能视觉主控”，而更像是：

> **一个挂在小车系统上的摄像头 + AP 网关 + TCP 串口桥接节点**

它的职责主要分为四类：

1. **启动摄像头并提供网页查看/采集能力**
2. **创建热点，允许手机或上位机直接接入**
3. **通过 TCP Socket 与外部控制端交换花括号协议消息**
4. **通过 Serial2 与车体主控板交换控制/状态消息**

---

## 4. 启动后的整体行为

ESP32-CAM 上电后，启动流程如下：

1. 初始化 `Serial` 和 `Serial2`
2. 初始化摄像头
3. 创建 Wi‑Fi SoftAP
4. 启动 HTTP 服务
5. 启动 TCP 服务器（端口 `100`）
6. 进入主循环
7. 在主循环中持续执行：
   - `SocketServer_Test()`
   - `FactoryTest()`

可以把系统理解成下面的结构：

```text
手机 / 浏览器 / App
        │
        ├── HTTP(80/81) → 摄像头网页、抓拍、视频流、状态查询、参数调节
        │
        └── TCP(100) → 花括号协议消息
                         │
                         ▼
                    ESP32-CAM
                         │
                  Serial2(UART2)
                         │
                         ▼
                     车体主控板
```

## 5. 网络与热点能力

### 5.1 工作模式

当前网络模式为：

- `WiFi.mode(WIFI_AP)`

即：

- ESP32-CAM 自己创建热点
- 外部设备直接连接该热点
- 不依赖家庭路由器或外部 AP

### 5.2 热点名称生成规则

热点 SSID 前缀为：

- `ELEGOO-`

随后拼接 ESP32 芯片 MAC 地址拆分后的十六进制字符串，因此最终热点名形如：

- `ELEGOO-XXXXXXXXXXXX`

其中：

- `wifi_name` 只保存 MAC 后缀部分
- 在工厂检测逻辑中会通过串口返回该值

### 5.3 密码

当前热点密码为空字符串，即：

- **开放热点**

这意味着连接方便，但安全性较低，适合调试与局域使用，不适合直接暴露在复杂网络环境中。

## 6. 摄像头初始化能力

### 6.1 当前摄像头型号

当前编译方案使用：

- `CAMERA_MODEL_AI_THINKER`

这意味着引脚映射来自 `include/camera_pins.h` 中的 AI Thinker 配置。

### 6.2 图像配置

初始化阶段采用 JPEG 输出：

- `pixel_format = PIXFORMAT_JPEG`

若检测到 PSRAM：

- 默认帧尺寸：`FRAMESIZE_UXGA`
- JPEG 质量：`10`
- Frame Buffer 数量：`2`

若未检测到 PSRAM：

- 默认帧尺寸：`FRAMESIZE_SVGA`
- JPEG 质量：`12`
- Frame Buffer 数量：`1`

初始化完成后，又会主动把传感器帧尺寸调整为：

- `FRAMESIZE_SVGA`

因此当前实际运行的默认工作分辨率更接近：

- `800x600`

### 6.3 图像翻转/镜像

当前默认设置为：

- `vflip = 0`
- `hmirror = 0`

即不做上下翻转、不做左右镜像。

## 7. 串口与车体主控协作

### 7.1 串口配置

当前使用：

- `Serial`：9600，用于调试输出
- `Serial2`：9600，用于与车体主控通信

UART2 引脚为：

- `RXD2 = 33`
- `TXD2 = 4`

### 7.2 通信消息格式

当前 TCP 与串口之间传输的是一类简单文本协议：

- 消息以 `{` 开始
- 以 `}` 结束
- 典型示例：
  - `{Heartbeat}`
  - `{"N":100}`
  - `{WA_detection}`

### 7.3 TCP → Serial2 转发

当 TCP 客户端发送一条完整花括号消息时：

- 如果消息是 `{Heartbeat}`
  - 仅用于心跳确认，不转发给主控
- 否则
  - 直接透传到 `Serial2`

### 7.4 Serial2 → TCP 转发

当 `Serial2` 收到一条完整花括号消息时：

- 直接发送给当前 TCP 客户端

这使得 ESP32-CAM 在系统中承担了：

> **网络命令与车体串口协议之间的桥接器**

---

## 8. TCP Socket 服务功能

### 8.1 监听端口

当前 TCP 服务监听在：

- 端口 `100`

### 8.2 单连接工作方式

主循环中通过 `server.available()` 获取客户端连接。

当前行为更偏向：

- 单客户端连接
- 当前客户端断开后，再等待下一个连接

### 8.3 心跳机制

ESP32-CAM 会每秒向 TCP 客户端发送一次：

- `{Heartbeat}`

若连续超过 3 次没有收到客户端的心跳回应，则判定连接失效并断开。

### 8.4 安全停车逻辑

以下情况下，ESP32-CAM 会通过 `Serial2` 向车体主控发送：

- `{"N":100}`

该消息在当前代码中被用作“停止命令”。

触发条件包括：

- TCP 客户端断开
- 心跳超时
- SoftAP 下已无设备连接
- 首次检测到客户端离线

因此当前系统具备一层基础失联保护能力。

## 9. 指示灯与工厂检测逻辑

### 9.1 LED 引脚

当前使用：

- GPIO `13`

### 9.2 指示灯行为

当有设备连接到 SoftAP 时：

- LED 常亮（代码中表现为输出低电平）

当没有设备连接时：

- LED 以约 `100ms` 周期闪烁

### 9.3 工厂检测命令

通过 `Serial2` 接收到以下命令时，ESP32-CAM 会返回对应结果：

| 输入命令 | 返回内容 | 说明 |
|---|---|---|
| `{BT_detection}` | `{BT_OK}` | 蓝牙检测占位反馈 |
| `{WA_detection}` | `{<wifi_name>}` | 返回当前热点名后缀 |

此外，网络连接状态还会通过串口发送：

| 输出命令 | 含义 |
|---|---|
| `{Factory}` | 启动后向主控声明进入工厂/自检流程 |
| `{WA_OK}` | 已检测到 Wi‑Fi 连接设备 |
| `{WA_NO}` | 当前没有 Wi‑Fi 连接设备 |

## 10. HTTP 服务整体说明

### 10.1 服务端口

当前 HTTP 服务启动了两套 `httpd`：

1. **主 HTTP 服务**
   - 默认端口：`80`

2. **视频流服务**
   - 在默认配置基础上 `server_port + 1`
   - 因此默认端口通常为：`81`

### 10.2 访问方式

连接 ESP32-CAM 热点后，默认可通过：

- `http://192.168.4.1/`

访问主页面。

### 10.3 当前 HTTP 功能边界

当前 HTTP 功能已经可以正常提供：

- 首页
- 摄像头状态查询
- 摄像头参数调节
- 单帧抓拍
- MJPEG 视频流
- 若干测试接口

### 10.4 当前未启用的人脸检测/识别功能

为了适配当前 PlatformIO + Arduino 的可编译环境，当前代码中：

- `ENABLE_FACE_DETECTION = 0`

这意味着当前版本：

- **不依赖 `fd_forward.h` / `fr_forward.h`**
- **不启用人脸检测**
- **不启用人脸识别**

因此，现阶段 HTTP 功能聚焦于：

> **基础图像采集、流媒体与摄像头参数调节**

## 11. HTTP 接口清单

### 11.1 首页

#### 接口

- `GET /`

#### 功能

- 返回内置的压缩 HTML 页面
- 浏览器打开后可作为摄像头控制页面

#### 说明

- 会根据传感器 PID 返回不同页面资源：
  - OV3660 页面
  - OV2640 页面

### 11.2 摄像头状态查询

#### 接口

- `GET /status`

#### 功能

- 返回当前摄像头参数状态，格式为 JSON

#### 返回字段

当前代码中会返回以下典型字段：

- `framesize`
- `quality`
- `brightness`
- `contrast`
- `saturation`
- `sharpness`
- `special_effect`
- `wb_mode`
- `awb`
- `awb_gain`
- `aec`
- `aec2`
- `ae_level`
- `aec_value`
- `agc`
- `agc_gain`
- `gainceiling`
- `bpc`
- `wpc`
- `raw_gma`
- `lenc`
- `vflip`
- `hmirror`
- `dcw`
- `colorbar`
- `face_detect`
- `face_enroll`
- `face_recognize`

#### 当前说明

虽然 JSON 中仍包含：

- `face_detect`
- `face_enroll`
- `face_recognize`

但在当前版本中，这三项仅保留字段兼容性，不代表检测/识别功能已启用。

---

### 11.3 摄像头参数设置

#### 接口

- `GET /control?var=<name>&val=<value>`

#### 功能

- 修改摄像头传感器参数

#### 支持的 `var` 参数

| 参数名 | 含义 |
|---|---|
| `framesize` | 分辨率 |
| `quality` | JPEG 质量 |
| `contrast` | 对比度 |
| `brightness` | 亮度 |
| `saturation` | 饱和度 |
| `gainceiling` | 增益上限 |
| `colorbar` | 彩条测试 |
| `awb` | 自动白平衡 |
| `agc` | 自动增益控制 |
| `aec` | 自动曝光控制 |
| `hmirror` | 左右镜像 |
| `vflip` | 上下翻转 |
| `awb_gain` | 白平衡增益 |
| `agc_gain` | 自动增益值 |
| `aec_value` | 曝光值 |
| `aec2` | 二级自动曝光 |
| `dcw` | Downsize 相关开关 |
| `bpc` | 黑点校正 |
| `wpc` | 白点校正 |
| `raw_gma` | Gamma 相关开关 |
| `lenc` | 镜头校正 |
| `special_effect` | 特效 |
| `wb_mode` | 白平衡模式 |
| `ae_level` | 自动曝光等级 |
| `face_detect` | 当前版本固定关闭 |
| `face_enroll` | 当前版本固定关闭 |
| `face_recognize` | 当前版本固定关闭 |

#### 返回

- 成功：空响应，HTTP 200
- 失败：HTTP 500 或 404

#### 示例

- 设置分辨率：
  - `GET /control?var=framesize&val=7`

- 设置 JPEG 质量：
  - `GET /control?var=quality&val=12`

- 设置镜像：
  - `GET /control?var=hmirror&val=1`

## 12. 典型使用方式

### 12.1 浏览器查看视频

1. 连接 ESP32-CAM 热点
2. 浏览器打开：
   - `http://192.168.4.1/`
3. 或直接访问：
   - `http://192.168.4.1/capture`
   - `http://192.168.4.1:81/stream`

### 12.2 动态调节摄像头参数

例如把分辨率改成 `SVGA`：

- `http://192.168.4.1/control?var=framesize&val=7`

例如打开左右镜像：

- `http://192.168.4.1/control?var=hmirror&val=1`

### 12.3 使用 TCP 控制链路

1. 连接到 ESP32-CAM 热点
2. 建立到端口 `100` 的 TCP 连接
3. 按花括号协议发送消息：
   - `{Heartbeat}`
   - `{"N":100}`
   - 其他控制指令
4. ESP32-CAM 将非心跳消息透传到 `Serial2`

## 13. 当前限制

### 13.1 人脸检测/识别未启用

当前版本为了保证在当前工程环境中稳定构建，已关闭：

- 人脸检测
- 人脸识别
- 人脸框绘制

### 13.2 热点为开放网络

当前密码为空：

- 安全性较弱

### 13.3 HTTP 接口以历史示例改造为主

因此存在一些特点：

- `/Test`、`/test1`、`/test2` 仍然保留
- `face_*` 参数接口仍保留，但当前不生效
- 部分命名仍带有原工程示例风格

### 13.4 TCP 协议是业务私有协议

当前 TCP 与 `Serial2` 使用的都是项目内部协议，主要特点：

- 文本协议
- 花括号包围
- 未做版本协商与消息校验

## 15. 后续建议

如果后续需要继续增强 ESP32-CAM 分支，建议优先考虑以下方向：

1. **补全文档与主说明的一致性**
   - 当前总说明中对 ESP32 分支的描述已落后于现状

2. **恢复或重建人脸检测能力**
   - 需要引入兼容的 ESP-WHO / 旧版人脸识别依赖组合

3. **完善 HTTP 接口协议**
   - 为 `/test1`、`/test2` 等接口明确业务用途

4. **增强网络安全**
   - 为 SoftAP 增加密码
   - 对控制接口增加访问约束

5. **规范 TCP 协议**
   - 明确消息字典、错误码与状态码

## 16. 文档结论

当前项目中的 ESP32-CAM 已经不再只是“预留入口文件”，而是具备了较完整的可运行模块：

- 能启动摄像头
- 能建立热点
- 能提供 HTTP 图像服务
- 能与主控通过串口协同
- 能通过 TCP 完成网络侧控制桥接

只是它目前仍属于：

> **功能已成形，但接口与高级视觉能力仍待继续工程化完善** 的阶段。
