# WALL-E 智能避障与循迹小车代码逻辑解析

本文档旨在详细解析 `WALL-E` 二轮小车的控制逻辑。该小车能够在 30-50cm 宽的S弯赛道中，利用前端的超声波传感器和舵机实现平滑的居中循迹以及智能的紧急避障。

## 1. 核心架构与状态机

程序的整体控制采用了一个简易的 **有限状态机 (Finite State Machine)** 设计。小车在运行过程中只会处于以下两种状态之一：

1.  **`STATE_NORMAL` (正常行进状态)**：在这个状态下，小车会不断进行小角度的快速扫描，利用 PID 算法调整左右轮速度，使得小车始终朝着空间最开阔（距离最远）的方向前进。
2.  **`STATE_OBSTACLE` (紧急避障状态)**：当正前方（中间区域）探测到距离过近的障碍物时，小车会紧急刹车并切换到此状态。此时，小车会进行一次全景的大角度扫描，找出最安全的逃生方向，并执行原地转向，随后恢复正常行进。

这两种状态的切换在 `loop()` 函数中进行调度：
```cpp
void loop() {
    if (currentState == STATE_NORMAL) {
        handleNormalState();
    } else if (currentState == STATE_OBSTACLE) {
        handleObstacleState();
    }
}
```

## 2. 正常行进状态 (`STATE_NORMAL`) 详细逻辑

在 `handleNormalState()` 中，小车需要同时完成“看”（雷达扫描）和“走”（马达控制）两个动作。

### 2.1 非阻塞式的雷达扫描
为了不影响小车的行驶平顺性，舵机的扫描不能使用 `delay()` 进行阻塞。代码通过记录时间戳 `millis()` 来实现非阻塞更新：
- 舵机以 `SERVO_CENTER` (80度) 为中心。
- 扫描范围由 `SERVO_SCAN_AMP` (50度) 决定，即在 30度 到 130度 之间来回摆动。
- 每次经过 `SERVO_SCAN_DELAY` (5ms) 后，角度改变 `SERVO_SCAN_SPEED` (5度)。

### 2.2 空间距离感知
随着舵机的摆动，超声波传感器不断读取前方的距离。代码根据舵机当前所处的角度，将前方的空间划分为左、中、右三个区域：
- **左侧**：舵机角度 > 95度，更新 `dist_left`。
- **右侧**：舵机角度 < 65度，更新 `dist_right`。
- **正前方**：舵机角度在 65 到 95 度之间，更新 `dist_center`。
  * **避障触发**：如果探测到 `dist_center` 的距离小于安全阈值 `OBSTACLE_DIST_THRES` (20cm)，小车会立即触发紧急停车，并将状态切换为 `STATE_OBSTACLE`。

### 2.3 PID 循迹算法
为了在 S 弯中居中行驶，代码采用了 PID 算法动态调整左右轮速度。
1.  **误差计算**：定义误差 `error = cap_left - cap_right`。
    - 如果左边更开阔（距离大），`error` 为正，我们希望车向左转。
    - 为了防止空旷场地数据过大导致计算崩溃，将测得的距离限制在 `MAX_TRACK_WIDTH` (50cm) 内。
2.  **PID 计算**：利用比例(Kp)、积分(Ki)、微分(Kd)计算出需要调整的速度补偿量 `turn_speed`。
3.  **速度分配**：
    - `speedL = BASE_SPEED - turn_speed`
    - `speedR = BASE_SPEED + turn_speed`
    - 举例：当 `error` 为正（需左转）时，`turn_speed` 为正，右轮加速，左轮减速，从而实现左偏。最后对计算出的速度进行限幅（40 ~ 200），确保电机运转正常。

## 3. 紧急避障状态 (`STATE_OBSTACLE`) 详细逻辑

当小车正前方被堵死时，进入 `handleObstacleState()`。

### 3.1 寻找生机（全景扫描）
1.  小车从 0度 到 160度，每隔 20度 停顿一次 (`delay(100)`) 并测量距离。
2.  遍历过程中，记录下测量到**最大距离** (`max_dist`) 及其对应的**最佳角度** (`best_angle`)。
3.  扫描结束后，舵机迅速归中。

### 3.2 脱困与转向
计算最佳角度与正前方的差值 `angle_diff = best_angle - SERVO_CENTER`。

- **死胡同处理**：如果全景扫描后发现最远距离依然小于安全阈值（四周都被堵死），小车会执行后退操作，并随机向右原地旋转一定角度，试图寻找新的出路。
- **原地打盘转向**：如果找到了安全方向，小车会根据角度差 `angle_diff` 估算出一个转向时间（时间常数 `8` 是一个经验值，需要根据实际轮胎摩擦力微调）。
  - **需左转** (`angle_diff > 10`)：左轮后退，右轮前进。
  - **需右转** (`angle_diff < -10`)：左轮前进，右轮后退。
- 转向完成后，小车刹车，将 PID 相关的历史变量（积分、历史误差等）清零，防止由于转向瞬间的数据突变导致后续循迹抽搐。
- 状态切回 `STATE_NORMAL`，继续前进。

## 4. 硬件控制底层

### 4.1 超声波读取 (`readSonar`)
采用标准的触发-回响时序：发送 10 微秒的脉冲给 `TRIG` 引脚，然后使用 `pulseIn()` 测量 `ECHO` 引脚高电平的持续时间。为防止传感器故障导致程序死锁，`pulseIn()` 设定了 30000 微秒的超时时间（约对应5米距离）。

### 4.2 电机驱动 (`setMotorSpeed`)
基于 TB6612 驱动芯片：
- 通过控制 `IN1/IN2` (或 `IN3/IN4`) 的高低电平组合来实现电机的正转和反转。
- 通过给 `EN` (PWM) 引脚输出模拟值（0-255）来控制速度。
- 包含了一个方便的配置项 `MOTOR_LEFT_INVERT` / `MOTOR_RIGHT_INVERT`，如果发现电机接线导致转向相反，只需在配置文件中修改此宏即可在代码层面纠正，无需重新插拔硬件。
